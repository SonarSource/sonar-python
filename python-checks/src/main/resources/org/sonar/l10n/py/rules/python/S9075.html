This is an issue when test code verifies that a warning was emitted without specifying its type, or when it uses the overly broad base Warning type without checking the message.

In Python with pytest, this refers to underspecified pytest.warns() usage, such as:

  • Calls without an expected warning type, for example pytest.warns()
  • The base type Warning without a match parameter

More specific warning types such as UserWarning or DeprecationWarning are not covered by this rule when used without match=.

Why is this an issue?

When testing that code emits a warning, it is not sufficient to verify only that some warning was raised. Tests should also validate the warning type or message to differentiate expected warnings from unexpected ones.

Consider a function that should emit a DeprecationWarning when given a legacy argument. If your test only checks that a warning occurred, it cannot distinguish between:

  • The expected DeprecationWarning indicating proper deprecation signaling
  • An unexpected UserWarning from a different code path
  • An unexpected ResourceWarning from a resource leak

All three scenarios would make the test pass, even though two represent unintended behavior.

In pytest, the following patterns lead to insufficiently specific warning testing:

  • Using pytest.warns() without an expected warning type
  • Using pytest.warns(Warning) without match=

The base Warning class is the root of the warning hierarchy and catches every warning subtype. More specific types such as UserWarning or DeprecationWarning are accepted without match=.

These patterns create fragile tests that may pass for the wrong reasons, allowing regressions to slip through undetected.

What is the potential impact?

Tests that underspecify expected warnings can pass when an unrelated warning is emitted, leaving regressions undetected. Narrowing the expected type and message keeps warning tests as a reliable safety net.

How to fix it

Pass a specific warning type to pytest.warns. When using the base Warning type, add match= with a pattern for the message.

Code examples

Noncompliant code example

import warnings
import pytest

def test_warns_without_type():
    with pytest.warns():  # Noncompliant: no expected warning type
        warnings.warn("x", UserWarning)

def test_warns_broad_type():
    with pytest.warns(Warning):  # Noncompliant: base Warning without match=
        warnings.warn("deprecated", DeprecationWarning)

Compliant solution

import warnings
import pytest

def test_warns_without_type():
    with pytest.warns(UserWarning):
        warnings.warn("x", UserWarning)

def test_warns_broad_type():
    # Base Warning is allowed when match= narrows the expected message
    with pytest.warns(Warning, match="deprecated"):
        warnings.warn("deprecated", DeprecationWarning)
